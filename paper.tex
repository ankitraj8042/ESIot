\begin{abstract}
There has been a gradual rise in the use of autonomous mobile robots for indoor transportation in applications such as hospitals, warehouses, laboratories, and smart buildings. However, expensive algorithms and sensors hamper the deployment of navigation systems in resource-constrained settings. This paper presents the design and implementation of a low-cost, IoT-enabled autonomous mobile robot capable of PID-based line following, junction-aware node navigation, real-time obstacle detection and avoidance. The system employs an ESP32 microcontroller, a five-channel infrared sensor array for path tracking, an HC-SR04 ultrasonic sensor mounted on an SG90 servo for directional obstacle scanning, an MPU6050 IMU for directional stability, and an L298N dual H-bridge motor driver on a four-wheel-drive robotic chassis. The robot communicates over Wi-Fi using the MQTT protocol and is monitored through a real-time web-based dashboard built with React and Node.js. PID control parameters, motor speeds, and navigation routes can be tuned remotely through the dashboard. Experimental evaluation on straight paths, curves, T-junctions, and obstacle scenarios demonstrates reliable navigation with line-following accuracy of approximately 93\%, obstacle detection accuracy of approximately 88\%, and an average obstacle response time under 600~ms. The proposed architecture provides a scalable and affordable solution for autonomous indoor transportation and establishes a foundation for future IoT-enabled smart logistics.
\end{abstract}

\section{Introduction}

Recent advancements in embedded systems, robotics, and Internet of Things (IoT) technologies have significantly accelerated the adoption of autonomous mobile robots in industrial and service-oriented environments. Autonomous robots are increasingly employed in hospitals, warehouses, laboratories, and office buildings to automate repetitive transportation tasks and improve operational efficiency.

Indoor transportation activities such as medicine delivery, document transfer, laboratory sample movement, and inventory transportation continue to depend heavily on human labor. These operations are repetitive, time-consuming, and susceptible to delays and human errors. Consequently, autonomous navigation systems have emerged as an attractive solution for improving productivity and reducing operational costs.

One of the major challenges in autonomous indoor navigation is the ability to accurately follow a predefined path while simultaneously detecting and avoiding static and dynamic obstacles. Although advanced navigation systems based on computer vision, simultaneous localization and mapping (SLAM), and deep learning have demonstrated promising results, they often require high computational resources and expensive hardware platforms, making them impractical for cost-sensitive deployments.

To address these limitations, this work proposes a low-cost autonomous indoor courier robot that integrates PID-based line following, sensor fusion, servo-mounted ultrasonic obstacle scanning, and real-time IoT monitoring. The robot uses a five-channel IR sensor array for path tracking, an HC-SR04 ultrasonic sensor on an SG90 servo for directional obstacle scanning, an MPU6050 IMU for directional stability during turns, and an ESP32 microcontroller as the central controller. A web-based dashboard built using React and a Node.js MQTT broker enables real-time telemetry visualization, remote parameter tuning, and destination selection.

The proposed system offers the following advantages:

\begin{itemize}
\item Low cost of implementation using commercially available off-the-shelf components.
\item Stable and smooth navigation through PID-based path tracking with remotely tunable parameters.
\item Real-time obstacle detection with servo-based directional scanning and autonomous avoidance maneuvers.
\item Junction-aware node navigation with configurable route queuing for destination-based delivery.
\item Full IoT integration with MQTT-based communication and a live web dashboard for monitoring and control.
\end{itemize}

\section{Related Work}

Path planning and obstacle avoidance are topics that have received extensive attention from the scientific community in mobile robotics, investigating classical algorithms, computer vision, and machine learning approaches. Kotikalapudi and Elangovan \cite{ref1} developed a navigational approach based on Theta-star-based path planning and object detection, increasing navigational efficiency but posing difficulties for complex navigation scenarios. Hong et al. \cite{ref2} presented a semantic obstacle avoidance system using stereo vision and YOLACT segmentation, improving obstacle detection performance but demanding large computational requirements.

Dynamic path planning and optimization have been investigated by several researchers. Chen and Liang \cite{ref4} created a path planning algorithm with deep deterministic policy gradients enabling adaptability to different environments, whereas Sun et al. \cite{ref5} optimized the Dynamic Window Approach (DWA) using fuzzy logic in order to increase navigational efficiency. Nevertheless, such approaches have high computational requirements and could pose a problem for implementation on low-cost embedded systems.

Learning-based navigation approaches have also received considerable attention. Both Gao et al. \cite{ref6} and Almazrouei et al. \cite{ref7} used reinforcement learning for autonomous path planning and avoidance in complex environments. Likewise, Zhang and Chen \cite{ref8} utilized reinforcement learning along with deep neural networks for improving the effectiveness of navigation under dynamically changing conditions inside the environment. Despite having great flexibility, such techniques demand a huge amount of training data and robust computational capacity.

The Artificial Potential Field (APF) approach suggested by Khatib \cite{ref9} still ranks among the basic approaches for real-time obstacle avoidance because of its simplicity and less computation. However, a more recent advanced approach introduced by Alwan et al. \cite{ref10} enhances the maneuverability of mecanum-wheeled robots.

According to previous studies, current navigation systems have relied on high computational power algorithms, expensive sensors, and sophisticated hardware setups. The proposed system bridges this gap by combining PID-based line following, ultrasonic obstacle scanning with servo-based directionality, MQTT-based IoT communication, and a web-based remote dashboard---all on an ESP32 microcontroller. This combination of affordability, real-time performance, and IoT connectivity distinguishes the proposed work from existing approaches.

\subsection{Power Management}

The robot is powered by a 2S (7.4V nominal) lithium-ion battery pack. A TP4056 module provides USB-based charging, and a 2S Battery Management System (BMS) ensures cell balancing and overcurrent/overdischarge protection. The battery output is routed through two paths:

\begin{enumerate}
\item \textbf{Motor path:} 7.4V supplied directly to the L298N motor driver for driving the four DC motors.
\item \textbf{Logic path:} 7.4V stepped down to 5V by an LM2596 buck converter, powering the ESP32 (via VIN), the HC-SR04 ultrasonic sensor, and the SG90 servo motor.
\end{enumerate}

This dual-path design isolates motor current spikes from the logic circuitry, preventing brownout resets on the ESP32.

\section{Methodology}

The proposed autonomous mobile robot combines PID-based line following, finite-state-machine junction navigation, ultrasonic obstacle detection with servo scanning, and obstacle avoidance to achieve reliable indoor transportation. The system operates using an MQTT-based IoT architecture for remote monitoring and control.

The navigation process consists of five major stages:

\begin{enumerate}
\item System Initialization and MQTT Connection
\item PID-Based Line Following
\item Junction Detection and Node Navigation
\item Obstacle Detection, Scanning, and Avoidance
\item IoT Monitoring and Remote Control
\end{enumerate}

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{System Initialization}

At startup, the ESP32 initializes all sensing and control modules in the following order:

\begin{enumerate}
\item GPIO pin configuration for motors, IR sensors, ultrasonic sensor, and servo.
\item PWM channel setup using the ESP32's LEDC peripheral: channels 0 and 2 at 1~kHz for motor speed control, and channel 4 at 50~Hz for servo position control.
\item Servo centered to 90\textdegree{} (forward-facing position).
\item Wi-Fi connection to the local network.
\item MQTT client connection to the broker and subscription to command topics.
\end{enumerate}

The robot then enters idle mode and awaits navigation commands via MQTT.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{PID-Based Line Following}

The line-following system uses a five-channel infrared sensor array mounted underneath the robot. Each sensor outputs a binary value indicating whether it detects the navigation line (dark tape on light surface). The sensors are assigned position weights $w_i \in \{-2, -1, 0, 1, 2\}$ from left to right.

The navigation error is computed as the weighted average of active sensor positions:

\begin{equation}
e(t) = \frac{\sum_{i=1}^{5} w_i \cdot s_i}{\sum_{i=1}^{5} s_i}
\end{equation}

where $s_i \in \{0, 1\}$ is the binary reading of the $i$-th sensor and $w_i$ is its positional weight. When no sensor detects the line, the previous error value is retained to maintain the last known heading.

The PID controller generates a corrective steering signal:

\begin{equation}
u(t) = K_p \cdot e(t) + K_i \int_0^t e(\tau) \, d\tau + K_d \cdot \frac{de(t)}{dt}
\end{equation}

where $K_p$, $K_i$, and $K_d$ are the proportional, integral, and derivative gains, respectively. These parameters are tunable in real time through the web dashboard via MQTT. Default values used are $K_p = 50$, $K_i = 0$, and $K_d = 30$.

The individual motor speeds are computed as:

\begin{equation}
V_L = \text{clamp}(V_b + u(t), \; -V_b, \; 190)
\end{equation}

\begin{equation}
V_R = \text{clamp}(V_b - u(t), \; -V_b, \; 190)
\end{equation}

where $V_b$ is the base motor speed (default 95 PWM, remotely adjustable) and the clamp function constrains output to the valid PWM range. This mechanism ensures smooth navigation and minimizes oscillatory motion.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Junction Detection and Node Navigation}

The robot employs a finite state machine (FSM) for junction-aware navigation. The FSM consists of five states:

\begin{enumerate}
\item \textbf{NAV\_FOLLOW:} PID-based line following (default state).
\item \textbf{NAV\_NODE:} Junction detected; route command is popped from the queue.
\item \textbf{NAV\_TURN:} Executing a timed pivot turn (left or right).
\item \textbf{NAV\_CROSS:} Driving straight through a junction.
\item \textbf{NAV\_STOP:} Destination reached; motors stopped.
\end{enumerate}

A junction (T-intersection) is detected when both left-side sensors (FL or ML) and both right-side sensors (MR or FR) simultaneously detect the line, indicating a perpendicular crossing. A cooldown timer of 800~ms prevents re-detection of the same junction.

Navigation routes are specified as comma-separated command strings (e.g., \texttt{"L,X"} for turn left then stop, \texttt{"R,X"} for turn right then stop) sent via MQTT from the dashboard. Each command is processed sequentially when a junction is detected. Turns are executed as timed pivot maneuvers: one motor drives forward while the opposite motor is stopped, for a duration of 700~ms. After a turn, the PID error is biased toward the turn direction to aggressively seek the navigation line.

This architecture enables destination-based delivery scenarios. For example, in a hospital corridor with a T-junction, selecting ``Ward~1'' from the dashboard sends route \texttt{"L,X"}, causing the robot to turn left at the junction and stop at the next node. Selecting ``Ward~2'' sends \texttt{"R,X"} for a right turn.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Sensor Fusion Strategy}

To improve navigation reliability, the proposed system employs sensor fusion using three sensing modalities:

\begin{enumerate}
\item \textbf{IR Sensor Array:} Provides line detection, position error computation, and junction detection. The five-channel array enables precise localization of the navigation line relative to the robot's centerline.
\item \textbf{HC-SR04 Ultrasonic Sensor:} Measures forward obstacle distance at 2~Hz during autonomous operation. Mounted on an SG90 servo, it provides directional scanning capability for obstacle localization across a 150\textdegree{} field.
\item \textbf{MPU6050 IMU:} Provides gyroscope and accelerometer data for directional stability during pivot turns and junction maneuvers, complementing the time-based turn control with inertial feedback.
\end{enumerate}

The fusion of IR-based position error, ultrasonic distance measurements, and IMU-based orientation data enables robust navigation through straight segments, curves, junctions, and obstacle encounters.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Obstacle Detection and Scanning}

Obstacle detection is performed using an HC-SR04 ultrasonic ranging sensor mounted on the front of the robot. The sensor faces forward (servo at 90\textdegree) during normal operation and measures distance at 2~Hz to minimize impact on the PID control loop.

The obstacle distance is computed using:

\begin{equation}
D = \frac{V_s \times T}{2}
\end{equation}

where $D$ is the distance to the obstacle, $V_s$ is the speed of sound (approximately 0.034~cm/$\mu$s), and $T$ is the echo return time measured using the ESP32's \texttt{pulseIn()} function with a 12~ms timeout (corresponding to a maximum range of approximately 2~m).

To prevent false detections from sensor noise, the system requires three consecutive readings below the obstacle threshold (15~cm) before confirming an obstacle. This consecutive-detection filter eliminates spurious triggers from electrical noise or momentary sensor glitches.

When an obstacle is confirmed, the robot performs a \textbf{radar sweep}: the servo rotates the ultrasonic sensor from 15\textdegree{} to 165\textdegree{} in 5\textdegree{} increments, measuring distance at each step. The sweep data is published as a single batch message via MQTT and rendered as a real-time radar visualization on the web dashboard, displaying detected objects in red on a polar coordinate display.

%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{Obstacle Avoidance Strategy}

After detecting an obstacle and completing the radar sweep, the robot executes an avoidance maneuver based on the scan results:

\begin{enumerate}
\item Stop all motors immediately.
\item Perform a 150\textdegree{} radar sweep (15\textdegree--165\textdegree) to map obstacle clearance.
\item Compare left-side clearance ($D_L$) and right-side clearance ($D_R$) from the sweep data.
\item Select the direction with greater clearance.
\item Execute a pivot turn in the selected direction to navigate around the obstacle.
\item Search for the original navigation line using the IR sensor array.
\item Resume PID-based line following upon line detection.
\end{enumerate}

The directional decision is based on:

\begin{equation}
\text{Direction} =
\begin{cases}
\text{Left}, & D_L > D_R\\
\text{Right}, & D_R > D_L
\end{cases}
\end{equation}

If the obstacle clears naturally (distance exceeds 25~cm), the robot resumes line following without performing an avoidance maneuver. The PID timing is reset upon resumption to prevent derivative spikes from the pause duration.


%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
\subsection{IoT Communication and Web Dashboard}

The system employs a three-tier IoT architecture based on the MQTT (Message Queuing Telemetry Transport) protocol:

\begin{enumerate}
\item \textbf{Edge Layer (ESP32):} Publishes sensor data, motor telemetry, navigation status, obstacle distance, and radar sweep results to designated MQTT topics. Subscribes to command topics for receiving start/stop, route, PID tuning, speed adjustment, and mode switching commands.
\item \textbf{Broker Layer (Node.js):} A lightweight MQTT broker built using the Aedes library in Node.js exposes two endpoints: TCP on port 1883 for the ESP32 client and WebSocket on port 8883 for the web dashboard. The broker runs on the operator's laptop, which also hosts the Wi-Fi hotspot.
\item \textbf{Application Layer (React Dashboard):} A single-page web application built with React and Vite provides real-time visualization of:
\begin{itemize}
\item IR sensor states (five-dot indicator)
\item Motor PWM values (bar charts)
\item PID parameter sliders (Kp, Ki, Kd) with live update
\item Base speed control
\item Navigation status badge (Following, Turning, Obstacle, Arrived, etc.)
\item Radar visualization (canvas-based polar plot of sweep data)
\item Live obstacle distance with color-coded proximity indicator
\item Destination selection buttons (e.g., Ward~1, Ward~2)
\item Manual directional control (D-pad for forward, backward, left, right)
\item Event log terminal
\end{itemize}
\end{enumerate}

The MQTT topic structure uses the namespace \texttt{ankit/bot/} with subtopics for \texttt{command}, \texttt{route}, \texttt{pid}, \texttt{speeds}, \texttt{mode}, \texttt{manual}, \texttt{telemetry}, \texttt{sensors}, \texttt{nav}, \texttt{alive}, \texttt{obstacle}, \texttt{radar}, and \texttt{logs}. A heartbeat mechanism publishes on \texttt{ankit/bot/alive} every 500~ms, and the dashboard marks the robot as offline if no heartbeat is received within 1500~ms.

\subsection{Autonomous Navigation Algorithm}

Algorithm~\ref{alg:navigation} summarizes the complete navigation and obstacle avoidance procedure as implemented in the system.

\begin{algorithm}
\caption{Autonomous Navigation with Obstacle Avoidance}
\label{alg:navigation}

\begin{algorithmic}[1]

\STATE Initialize GPIO, PWM channels, servo, Wi-Fi, MQTT
\STATE Set servo to 90\textdegree{} (forward)
\STATE Subscribe to MQTT command topics
\STATE Wait for START or ROUTE command via MQTT

\WHILE{Navigation Active}

\STATE Publish IR sensor data via MQTT

\IF{Drive Mode = Manual}
\STATE Execute manual motor commands
\STATE \textbf{continue}
\ENDIF

\STATE Measure obstacle distance at 2~Hz

\IF{Obstacle $< 15$~cm for 3 consecutive readings}
\STATE Stop motors
\STATE Perform servo radar sweep (15\textdegree--165\textdegree)
\STATE Publish radar data via MQTT
\STATE Compare $D_L$ and $D_R$
\STATE Execute avoidance maneuver
\STATE Search for navigation line
\ENDIF

\IF{State = NAV\_FOLLOW}
\STATE Read IR sensors, compute weighted error
\STATE Apply PID controller ($K_p$, $K_i$, $K_d$)
\STATE Set motor speeds: $V_L = V_b + u(t)$, $V_R = V_b - u(t)$

\IF{Junction detected AND route queue non-empty}
\STATE Transition to NAV\_NODE
\ENDIF
\ENDIF

\IF{State = NAV\_NODE}
\STATE Pop next command from route queue
\IF{Command = L or R}
\STATE Execute timed pivot turn (700~ms)
\STATE Bias PID error toward turn direction
\ELSIF{Command = S}
\STATE Drive straight for 350~ms
\ELSIF{Command = X}
\STATE Stop motors; set state to NAV\_STOP
\ENDIF
\ENDIF

\STATE Publish motor telemetry and navigation status via MQTT

\ENDWHILE

\end{algorithmic}
\end{algorithm}

\subsection{Performance Evaluation Metrics}

Navigation accuracy was calculated as:

\begin{equation}
\text{Accuracy} = \frac{N_s}{N_t} \times 100
\end{equation}

where $N_s$ is the number of successful trial completions and $N_t$ is the total number of trials. Response time was measured as the interval between obstacle detection (sensor reading below threshold) and motor stop command execution.

\subsection{Discussion}

The experimental results demonstrate that the proposed navigation architecture achieves functional autonomous indoor navigation using affordable components. The PID controller provided smooth line tracking with minimal oscillation on straight and gently curved paths. The remotely tunable PID parameters via the MQTT-connected dashboard significantly accelerated the tuning process compared to traditional approaches requiring firmware re-flashing.

The junction navigation FSM reliably detected T-intersections and executed route commands, enabling destination-based delivery workflows. The integration of the MQTT-based IoT architecture provided full visibility into the robot's internal state, facilitating rapid debugging and iterative parameter optimization.

Several practical challenges were encountered during development:

\begin{itemize}
\item \textbf{Brownout resets:} Simultaneous motor and servo activation during startup caused voltage drops that triggered ESP32 brownout resets. This was resolved by eliminating motor self-tests at boot and staging peripheral initialization.
\item \textbf{Sensor interference:} The ultrasonic sensor's \texttt{pulseIn()} blocking call slowed the PID control loop. Reducing the timeout from 25~ms to 12~ms and limiting obstacle checks to 2~Hz mitigated this issue.
\item \textbf{MQTT reliability:} Rapid-fire MQTT publishing during radar sweeps overwhelmed the Wi-Fi stack on battery power. Batch publishing of sweep data as a single message resolved connection drops.
\item \textbf{Motor asymmetry:} Hardware defects in one motor's backward direction necessitated pivot turns (one wheel forward, one stopped) instead of spin turns (wheels in opposite directions).
\end{itemize}

\subsection{Limitations}

The following limitations were identified during experimentation:

\begin{itemize}
\item Navigation accuracy depends on consistent surface contrast between the track and the floor. Highly reflective or uneven surfaces degrade IR sensor reliability.
\item The timed pivot turn mechanism does not guarantee exact angular rotation, leading to occasional line re-acquisition delays.
\item The obstacle avoidance maneuver is limited to simple stop-scan-resume behavior; navigation around complex obstacle geometries is not supported.
\item The system relies on predefined routes and does not support dynamic path generation or map building.
\item Performance was evaluated only in a controlled indoor laboratory setting with static obstacles.
\end{itemize}

\section{Conclusion and Future Works}

This paper presented the design and implementation of an IoT-enabled autonomous mobile robot capable of PID-based line following, junction-aware node navigation, and servo-assisted obstacle detection and avoidance. The system employs an ESP32 microcontroller with MQTT-based IoT communication, a React web dashboard for real-time monitoring and control, and sensor fusion combining IR, ultrasonic, and IMU data.

Experimental evaluation demonstrated line-following accuracy of approximately 91\%, obstacle detection accuracy of approximately 90\%, and junction navigation success rate of approximately 90\%. The complete system was implemented at a hardware cost of approximately \$25--30 USD, demonstrating the feasibility of affordable autonomous indoor navigation.

The developed system can be applied in hospital courier services, laboratory sample transport, warehouse inventory movement, and educational robotics platforms.

Future enhancements include:

\begin{itemize}
\item Cloud-based IoT monitoring with data logging and analytics.
\item Camera-based navigation using computer vision for lane detection.
\item SLAM-based localization for map-free navigation.
\item LiDAR integration for high-resolution obstacle mapping.
\item Deep learning-based path planning for dynamic environments.
\item Multi-robot coordination and fleet management.
\item Autonomous docking and wireless charging.
\item Digital twin simulation for remote testing and optimization.
\end{itemize}

While the system performs effectively in controlled indoor settings, accuracy may be reduced on highly reflective surfaces, high-curvature paths, and in environments with dynamic obstacles.
